# Invitation fix and more business icons: production release v1.8.1 (CHQ-199, CHQ-200)

Released 2026-11-04 at the owner's request.

## What changed

- **Join after a failed Resend (customer bug, CHQ-199).** On 2026-11-02 Migadu refused `no-reply@klokka.se` (daily
  limit). Resend deletes the Logto invitation before it creates the new one; the create failed, Klokka's row rolled
  back to the deleted id, and every accept then got Logto 404 `entity.not_found` (two pending invitations in the
  workspace Solid Line; one invitee tried six times). On a Logto 404 the accept now adds the user to the
  organization with the member's role, the path already used for memberships without a Logto invitation. No data
  change was needed for the affected rows.
- **Business icons (CHQ-200).** `WORKSPACE_EMOJIS` moved to `@klokka/core`: 29 icons with catalogue names
  (`workspace.emojis.*`), used by the web and phone pickers (create and settings). The API stores any emoji.

## Test

- Local: the repro test `InvitationResourceTest.acceptingStillJoinsWhenLogtoNoLongerHasTheInvitation` failed first
  (500) and passes now; invitation, member and operator API tests; core 68, web 113, mobile 198; typecheck, lint,
  em dash and catalogue checks green. `OperatorResourceTest.resendIsTheOnlyMutationAndVolumeCountsTheLedger` fails
  when run alone on a clean `main` too (it depends on other tests' rows); it passes in the full suite in CI.
- Web picker: Playwright on the dev server at 360, 430 and 1280 px, 29 icons, no horizontal overflow.
- Staging: CI green for both commits, API, web, landing and APK deployed.
