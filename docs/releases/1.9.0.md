# Analytics with consent: production release v1.9.0 (CHQ-201)

Released 2026-11-05 at the owner's request (a minor tag after staging was verified end to end).

## What changed

- **klokka.se: Google Analytics only after consent.** Google Tag Manager `GTM-P6RRM6CL` loads only after Accept on
  the cookie card (basic consent mode: nothing from Google before the answer). One container serves every build: a
  hostname lookup sends klokka.se to GA4 "Klokka" (`G-NJCCFQD2L6`) and any other host to "Klokka (staging)"
  (`G-RES1DTS3EG`). Cookie settings in the footer reopens the card; No thanks after a yes clears the `_ga` cookies.
  Site events: `sign_up_click`, `login_click`, `apk_download`, `template_download` with a placement. The privacy
  policy names GA (consent) and Umami (legitimate interest). The CSP lists Google's hosts only on a build with a
  container id.
- **Web app and phone app: cookieless Umami.** Page and screen views plus `workspace_created`, `invitation_sent` and
  `hours_saved`, with paths cleaned by `analyticsPath` in `@klokka/core` (workspace slug, ids and dates replaced).
  Umami 3.4.1 runs on staging Coolify (`a4zjdk8zgumdaqfxh3el0gtq`); production and staging are separate websites
  (`docs/OPERATIONS.md` section 3a, `docs/DECISIONS.md` D24).
- **Cleanup.** The Firebase-made GA property `klokka-64f3a` is in GA's trash and the old Firebase Android app
  `com.prasannjeet.klokka` is removed.
- **Test fix.** `RecurrenceEditor.test.tsx` waits for the repeat sentence (it failed CI run 41923937044 under load).
