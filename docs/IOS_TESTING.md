# iOS: building and testing Klokka

Klokka's phone app is one Expo project (`apps/mobile`) for Android and iOS, but so far only Android has been built
and tested: this host is Ubuntu, and iOS apps can only be compiled on macOS with Xcode. This page is for a session
that has iOS access (a Mac, or an Apple Developer account for Expo's cloud builds) and an iPhone.

## What exists for iOS already

- `apps/mobile/app.config.ts`: `ios.bundleIdentifier` is `se.klokka.app` (the same id as Android, D19), no tablet
  support, background mode for remote notifications. `ios/` is generated by `expo prebuild` and gitignored, like
  `android/`.
- The job location map (CHQ-163, `src/features/jobs/PlaceMap.tsx`) draws **Apple Maps** on iOS through `expo-maps`:
  no key is needed. Search, place details and "name the spot under the pin" go through our API (Google Places with
  the server key), exactly as on Android. Design: https://claude.ai/artifact/L5cEibPPEkgC1qhoge2oxx (iOS row).
- Sign-in uses the same Logto native app and the `klokka://auth/callback` redirect as Android.

## Not set up yet (decide before the first iOS build)

- An Apple Developer account (paid) and the App ID `se.klokka.app` in it.
- Push notifications: an APNs key uploaded to Expo (EAS credentials) so `expo-notifications` can deliver on iOS.
  Without it the app works, but no push arrives.
- Location permission text: `NSLocationWhenInUseUsageDescription` must be set in `app.config.ts` (`ios.infoPlist`) in
  Swedish and English before "Use where I am now" can work; iOS rejects a location request without it.
- App Store Connect record and TestFlight testers, if the build should reach phones without a Mac.

## Two ways to build

1. **On a Mac with Xcode** (fastest loop, the simulator works):

   ```sh
   cd apps/mobile
   npx expo prebuild --platform ios --clean
   npx expo run:ios            # simulator; add --device for a cabled iPhone
   ```

   Runtime values come from `apps/mobile/.env` (`EXPO_PUBLIC_*`), as on Android: point them at **staging** (see
   `apps/mobile/.env.example`). Never test against production.

2. **From any host with Expo's cloud builders (EAS Build)**: needs the Apple Developer account and `EXPO_TOKEN`
   (`.agents/local-credentials/expo.json`). `eas build --platform ios --profile preview` builds on Expo's Macs; the
   result installs through TestFlight or an ad-hoc link. This Ubuntu host can start such a build, but it cannot run
   a simulator or drive an iPhone, so the hands-on test still needs the phone.

## What to test (staging, both light and dark mode)

Use the staging employer account from `.agents/local-credentials/staging-accounts.json`.

1. Sign in, sign out, sign in again (Custom Tab hand-off and the `klokka://` redirect).
2. Home, Week, Insights, Settings render without overlap at the iPhone's size and with Dynamic Type one step larger.
3. **Job location (CHQ-163):** open a person's day, add a job, tap **Location**:
   - the full-screen picker opens on Apple Maps; "Back" (top left) closes it without changes;
   - typing two or more letters shows results in a fixed area above the keyboard; the screen must not jump as the
     number of results changes; "Places by Google" shows under the results;
   - tapping a result moves the map there with the pink pin in the middle and the place's name and address below;
   - dragging the map renames the place after the spot under the pin (after the map stops);
   - **Use this place** returns to the job, which shows the place and a small map preview; saving the job keeps it;
   - "Use where I am now" asks for location once (needs the Info.plist text above);
   - "No location for this job" clears it.
4. Recurring jobs: Repeat, weekly with two days, ends after 4 weeks; the preview lists the dates; save, then remove
   with "Stop this and future jobs".
5. Push (only once APNs is set up): flag an entry as the employee, the employer gets a notification.

Take screenshots of each step (light and dark) and attach them to the Jira ticket you test under; note the iPhone
model and iOS version.

## Known differences from Android

- Apple Maps instead of Google Maps (by design: no key, free, native look).
- The back control in the picker is "‹ Back" in the accent colour (the iOS convention); Android shows an arrow.
- `expo-maps` reports camera moves on iOS too; if a drag does not rename the place on iOS, check `onCameraMove` in
  `PlaceMap.tsx` first (Android was the platform it was verified on).
